Сборки и агенты программирования продолжают работу при обрыве соединения клиента или VPN; вернитесь в ту же интерактивную оболочку с её переменными и рабочим каталогом; просмотрите сохранённый вывод: воспроизведение ограничено, это не полный журнал. Windows на обеих сторонах; хост работает, пользователь остаётся в системе. После перезагрузки хоста или выхода пользователя восстановления нет.

*Это схема рабочего процесса, а не снимок реального сеанса и не доказательство тестирования. Подписи на изображении английские. Смысл: после отключения клиента можно вернуться к той же оболочке, переменным и работе на хосте, если он продолжает работать и пользователь остаётся в системе. После перезагрузки хоста процессы не восстанавливаются.*

- **Работа продолжается без клиента.** Сборки, агенты и долгие команды работают на удалённом Windows-хосте при закрытии клиента, потере VPN или перезагрузке ноутбука.
- **Вернитесь к работе, а не в пустую оболочку.** Подключитесь к тому же процессу интерактивной оболочки с его переменными и рабочим каталогом.
- **Просмотрите вывод за время отсутствия.** При подключении воспроизводится сохранённый вывод терминала; объём хранения ограничен, возможны пропуски, это не полный журнал.

Для обычных неинтерактивных задач может хватить уже одобренного канала удалённых команд. Выбирайте arTerm, когда после закрытия клиента, обрыва VPN или перезапуска ноутбука нужно вернуться в **ту же интерактивную оболочку Windows и её окружение, работающие на хосте**, соблюдая документированные условия подключения и локального управления. Обе стороны должны работать под Windows, хост должен оставаться включённым с вошедшим пользователем; после перезапуска хоста процессы не восстанавливаются.

## Требования и доверие

Подходит для Windows с обеих сторон, одного аккаунта GitHub в туннелях и разрешённых исходящих подключений. Хост должен работать, пользователь — оставаться в системе. Перезагрузка, выход пользователя, сбой или выключение хоста и exit оболочки не позволяют восстановить процесс. Текущие загрузки подписаны для разработки, это не производственные сборки с публично доверенной подписью.

[Проверьте загрузку и обдумайте доверие сертификату до установки](../../DEVELOPMENT-INSTALL.md). Не обходите предупреждения ОС или политику организации.

Клиенту и хосту нужен Windows. Хост должен работать, а пользователь — оставаться в системе. Клиент использует Microsoft devtunnel CLI; хост — совместимый нативный VS Code tunnel CLI, например code-tunnel.exe. Полный редактор необязателен. В обоих туннелях войдите в один аккаунт GitHub; авторизация gh этого не заменяет. Нужны разрешённые исходящие подключения, согласие на загрузку зависимостей и принятие лицензии VS Code server.

Выберите x64 или ARM64 в [загрузках Windows](https://github.com/yeelam/arterm/releases/latest). Опубликованная v0.7.1 подписана сертификатом разработки, а не публично доверенным производственным сертификатом. Сначала [сравните ZIP с опубликованной контрольной суммой](../../DEVELOPMENT-INSTALL.md#verify-the-downloaded-release-payload-before-trust-or-installation) этой версии через Get-FileHash. Хеш ZIP, идентичность CER и доверие подписи исполняемого файла — разные проверки. До запуска выполните [проверку без изменения системы](../../DEVELOPMENT-INSTALL.md#inspect-extracted-executable-signatures-without-running-them) через Get-AuthenticodeSignature для извлечённых установщиков и клиентов. Нужен подписант разработки, идентифицированный по указанному в руководстве отпечатку SHA-256 сертификата и статус Valid. Нет контрольной суммы, она не совпала, подписант неизвестен или статус не Valid — остановитесь. Доверие сертификату требует отдельного явного одобрения пользователя и разрешения политики, после чего проверку повторяют. Не обходите предупреждения ОС, Authenticode, SmartScreen и контроль приложений.

Хосту также нужен разрешённый политикой Windows Script Host/VBScript. Проверьте до доверия/установки; при блокировке остановитесь, не обходите политику.

## Настройка

Сохранённый вывод, обычная история оболочки и файлы восстановления могут содержать команды, пути, код и секреты. Защищайте их на обеих машинах и удаляйте чувствительные сведения из журналов, снимков и материалов поддержки перед отправкой. Защита учётных данных DPAPI не означает шифрование всех файлов или отсутствие содержимого. Исключения содержимого в диагностике готовности имеют более узкий охват.

После успешных проверок и разрешения политики запустите arTerm-Host-Setup.exe на хосте и откройте новый PowerShell:

```powershell
arterm-host setup --name my-devbox
```

Завершите вход в туннель и сохраните команду регистрации, напечатанную хостом. Локально установите arTerm-Client-Setup.exe, откройте новый PowerShell с тем же аккаунтом GitHub и выполните именно эту команду с фактическим путём хоста. Клиент уже инициализирован, arterm setup не нужен. Подключитесь локально с новым именем сеанса:

```powershell
arterm connect my-devbox MyProof --shell powershell
```

## Проверка той же оболочки

В подключённом удалённом PowerShell выполните и запишите PID и каталог:

```powershell
$artermProof = 'kept-on-host'
$artermPid = $PID
$artermCwd = (Get-Location).Path
$PID; $artermProof; (Get-Location).Path
```

Нажмите Ctrl+], чтобы отсоединить клиент. Если сочетание перехватывается, закройте только локальную вкладку клиента. Хост должен работать с вошедшим пользователем. Повторите ту же команду локально:

```powershell
arterm connect my-devbox MyProof --shell powershell
```

В повторно подключённом удалённом PowerShell:

```powershell
$PID; $artermProof; (Get-Location).Path
($PID -eq $artermPid) -and ($artermProof -eq 'kept-on-host') -and ((Get-Location).Path -eq $artermCwd)
```

Ожидаются прежний PID, kept-on-host, прежний каталог и True. В дальнейшем возвращайтесь той же командой. Для завершения проверки введите exit в удалённой оболочке: процесс завершится, его состояние уже не восстановить.

## Ограничения

Процессы не восстанавливаются после перезагрузки, выхода пользователя, сбоя или выключения хоста либо выхода из оболочки. Хост запускается при входе пользователя; автоматический вход и работа без вошедшего пользователя не настраиваются. Сохранённый вывод для повторного просмотра ограничен. Вся ветка разработки не квалифицирована для выпуска: независимая проверка архивов передачи файлов и условия прямого ввода остаются незавершёнными. Произвольные TUI не сертифицированы; автоматическое снятие блокировки файлов не гарантирует безопасность.

Повторный вывод ограничен; для полного вывода сохраняйте удалённый журнал сборки. arterm-host stop может запуститься автоматически; arterm-host stop --disable сохраняет остановку.

## Восстановление и отмена

При сбое используйте arterm doctor my-devbox, проверьте аккаунты и сеть; при необходимости восстановите вход клиента через arterm --login. Не удаляйте записи восстановления и не переустанавливайте работающий хост. Обновление по умолчанию не прерывает активные сеансы. На хосте arterm-host stop --disable сохраняет остановку; arterm-host start запускает его снова, но не возвращает потерянные оболочки. Удаление программы сохраняет данные. Отзыв доверия сертификату описан в руководстве.

## Расширенное локальное управление

Управляемые send/read требуют новой поддерживаемой сессии PowerShell/pwsh и совпадающей доверенной локальной идентичности подключения. Старые оболочки не дооснащаются. Публикация не закрывает проверки прямого ввода/архивов передачи в ветке; неизвестные версии остаются непроверенными.

Пользователи Copilot CLI, Claude Code, Codex, Gemini CLI, Kimi и Qwen CLI могут выполнять обычные команды Windows, если инструменты позволяют; это не сертификация нативной интеграции шести клиентов. Другому локальному терминалу управления нужны тот же пользователь, сеанс входа, уровень целостности/повышения прав и побайтно одинаковый доверенный подписанный клиент. Держите процесс подключения запущенным. Это не произвольный общий доступ агентов с разных машин.
